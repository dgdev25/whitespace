WHITESPACE / SHOWCASE ARCHITECTURE
One gated container with explicit non-live boundaries
The deployed preview serves React from FastAPI and stores only fixed synthetic data in SQLite. The source and model paths visible in the full product are deliberately unavailable in this hosted mode.

VISITOR EXPERIENCE

React frontend

Idea feed, static evidence, saved review, and prebuilt plan views labelled as a synthetic showcase.

↓
Invite gate

Gateway-issued visitor session, no-index boundary, expiry, logout, and UAT reporting controls.

APPLICATION CONTAINER

FastAPI service

Serves built frontend assets, read endpoints, static exports, and internal health/config endpoints.

↓
Showcase seed

Repairs or creates only the three reserved synthetic records and complete static product sketches.

↓
SQLite demo store

Self-hosted synthetic sources, scores, saved idea, and build outputs; no production user corpus.

DISABLED BOUNDARIES

Research ingestion

Source polling and organisation import are rejected before a network request can occur.

↓
Model generation

Build, PRD, and pipeline generation routes return 403; no provider credential is required.

↓
Operational checks

Container health, demo-mode config, invited browser acceptance, and synthetic-feed checks gate release.

READ-ONLY CONTRACT

The public Whitespace experience is a deterministic technical showcase. A future live research product needs separate data, retention, provider-budget, and deletion controls before this guard can be removed.
